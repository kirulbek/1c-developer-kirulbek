# Проекты, задачи и сохранение контекста

Проект — верхний уровень; внутри него задачи и история. Идентификаторы `ПР-1`, `ЗД-1` должны быть стабильными. Не путай эти рабочие карточки с чатами или проектами интерфейса Codex: команды Skill сами по себе не создают и не архивируют чаты.

## Начало и переключение

Если проект известен из текущего выбора, используй его до явного переключения. Если при начале задачи проект/конфигурация неизвестны и нужны для истории, один раз уточни название. Не задавай этот вопрос при каждом сообщении. При новом проекте настрой комментарии по comments.md. Сложный технический профиль не создавай; версии уточняй по необходимости задачи.

Новый режим не всегда означает новую задачу: проверка, отладка и исправление могут быть стадиями одного результата. Отдельную цель оформи отдельной задачей. При переключении сохрани точку незавершённой задачи, не перезаписывай её новой. Побочный вопрос не означает завершение основной задачи.

## Команды

| Команда/фраза | Поведение |
|---|---|
| /проекты | Показать проекты; по выбору переключить текущий, сохранив отдельный контекст каждого |
| /задачи | Показать незавершённые задачи текущего проекта, их ID, название, режим и статус; по просьбе — других/всех проектов |
| /пауза | Сохранить режим, цель, проверенные факты, исключённые и оставшиеся гипотезы, текущую точку и следующий шаг; статус «пауза» |
| /продолжить | Вернуться к последней приостановленной задаче текущего контекста; если такой нет или выбор неоднозначен, показать доступные задачи |
| Продолжить ЗД-1 | Восстановить конкретную задачу и её проект; кратко напомнить проверенное, текущую гипотезу и следующий шаг |
| /завершить | Уточнить недостающие итоги, сформировать карточку, сохранить в историю |
| /история | Показать завершённые задачи текущего проекта; по просьбе открыть карточку по ID или выбрать период/проекты |

Согласованное имя команды — `/завершить`, не `/стоп`. Обычное «остановись» уважай как прекращение текущих действий, но не считай доказательством, что задача решена.

## Завершение

Если ещё неизвестны, уточни **только два пункта**: фактически потраченное время и полностью ли решена задача (что осталось). Не переспрашивай уже сообщённое. Значение пользователя — окончательное для отчётности; не подменяй его длительностью переписки. Автоматические таймеры не нужны.

Короткая карточка содержит:

- ID, название, проект/конфигурацию, тип задачи, даты начала/завершения;
- что сделали; найденную причину, если применимо;
- что изменили; результат; что осталось;
- фактическое время со слов пользователя.

Завершённая карточка может содержать нерешённый остаток: явно отличай завершение работы над задачей от результата «полностью решена». Если пользователь не знает время, оставь его неизвестным, не придумывай. Если ответ ещё ожидается, сохрани статус «ожидает итога» и не называй карточку полностью заполненной.

История должна позволять открыть старую задачу, восстановить контекст и собрать месячный отчёт по датам, проектам, результатам и фактическому времени. Суммируй только известное время; неизвестное отметь отдельно. Не разрабатывай отдельную программу управления задачами: это отложено.

## Минимальное файловое сохранение

Чтобы история не зависела только от памяти одного чата, используй небольшой локальный журнал. Это реализация сохранения карточек, не отдельная система тайм-трекинга.

Используй постоянный каталог данных в `Documents/Codex/1c-developer-kirulbek-data/` текущего пользователя (в Windows разрешай `Documents` относительно текущего профиля). Если пользователь указал другое место — используй его. Данные держи отдельно от установленного Skill. Хранилище локально для каждого компьютера, пока пользователь отдельно не выберет общее облако.

Создавай файлы только при появлении реального проекта/задачи:

- `index.json`: версия формата, реестр проектов, пути к файлам, следующие номера ID. Не храни глобальный «текущий проект», который один чат незаметно переключит другому.
- `projects/PR-<номер>.json`: название и настройки комментариев `enabled` (true/false/null), `label`, `author`.
- `tasks/ZD-<номер>.json`: карточка задачи и точка продолжения. Пример полей: `id`, `project_id`, `title`, `mode`, `status`, `started_at`, `updated_at`, `completed_at`, `facts`, `excluded_hypotheses`, `open_hypotheses`, `current_step`, `next_step`, `context_refs`, `findings`, `summary`, `remaining`, `resolved`, `actual_time_text`, `actual_minutes`.

Текущий проект/задачу выбирай в контексте данного чата, а восстановление делай по явному ID/выбору. Коды файлов — ASCII PR/ZD, отображаемые ID — ПР/ЗД. Формат JSON, UTF-8; даты с часовым поясом. Неизвестное — null/явная отметка, а не выдуманные данные. Время в минутах заполняй лишь при однозначном переводе слов пользователя, оригинал сохраняй.

Перед изменением прочитай актуальные файлы; сохрани посторонние поля и карточки. При создании нового ID проверь, что его файл ещё не существует. Записывай через временный файл и атомарную замену, по одному изменению. Если файл изменился с момента чтения или ID уже занят, перечитай и согласуй изменения; не затирай параллельную работу. Держи предыдущую версию изменяемой карточки для восстановления. Не удаляй историю при завершении.

Сохраняй карточку при начале, паузе, существенном подтверждённом результате, переключении и завершении. Храни краткие факты и необходимые ссылки на код/файлы; не копируй всю конфигурацию, секреты и всю переписку. Если для точного продолжения отсутствует сам фрагмент кода, попроси его, не восстанавливай из догадок.

Если файловая запись недоступна, честно скажи, что постоянное сохранение не выполнено, и выдай компактную карточку в чате для восстановления. Не обещай память между чатами без доступного журнала. Не переписывай конфигурацию Codex и разрешения ради журнала.
