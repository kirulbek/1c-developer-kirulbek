# Подключение MCP-серверов 1С к Codex

Skill использует два отдельных MCP-сервера. Это локальные серверы вашей среды разработки, а не содержимое репозитория.

| Имя сервера в Codex | Для чего нужен | Ожидаемые инструменты |
|---|---|---|
| `onec_help` | Поиск и чтение установленной справки платформы 1С | `search`, `get_page`, `hierarchy`, `related`, `config_get` |
| `onec_bsl` | Статический анализ BSL-фрагмента, файла или известного модуля | `bsl_diagnostics` |

## Проверить подключение

Откройте PowerShell и выполните:

```powershell
codex mcp list
codex mcp get onec_help --json
codex mcp get onec_bsl --json
```

Команда `list` должна показывать оба сервера как доступные. `get` показывает, как именно текущий Codex запускает каждый MCP-сервер на этом компьютере. В выводе могут быть локальные пути — не публикуйте его целиком.

В текущем окружении Codex использует локальную stdio-команду для каждого сервера: `onec_help` запускает `v8help.exe --config v8help.toml serve`; `onec_bsl` запускает `python.exe -m bsl_ls_mcp`. На домашнем компьютере нужны сами эти программы/пакеты в подходящем Python/проектном окружении и корректная конфигурация. Точные абсолютные пути будут другими.

## Установить серверы и данные

Получите дистрибутивы `v8help` и `bsl_ls_mcp` из того же источника, из которого они поставлены на рабочий компьютер, либо у сопровождающего вашей среды. Репозиторий Skill не содержит этих MCP-программ.

Для `onec_help` настройте `v8help.toml` на справочные книги и локальную базу поиска. На текущем сервере справка настроена на русские книги контекста, встроенного языка, языка запросов и встроенного языка запросов. Индекс/корпус справки и установленная платформа 1С требуются локально. Используйте соответствующие пути именно домашнего компьютера; не копируйте пути вида `D:\...` с рабочей машины.

Для `onec_bsl` используйте тот интерпретатор Python, где установлен модуль `bsl_ls_mcp`. Он проверяет синтаксис и статические замечания; сам по себе сервер не знает метаданные конфигурации и не исполняет код в 1С.

После установки найдите на домашнем компьютере абсолютные пути к запускаемым файлам и добавьте серверы командами в PowerShell. Замените примеры путей своими:

```powershell
codex mcp add onec_help -- "C:\Путь\к\v8help.exe" --config "C:\Путь\к\v8help.toml" serve
codex mcp add onec_bsl -- "C:\Путь\к\python.exe" -m bsl_ls_mcp
```

Если сервер уже существует под другим именем, не добавляйте дубликат: либо используйте существующее имя `onec_help` / `onec_bsl`, либо скорректируйте конфигурацию согласно `codex mcp add --help`. Поле `cwd` может понадобиться, если установленный сервер зависит от текущего каталога; его тоже задайте через актуальную конфигурацию Codex.

## Проверить работу

После добавления:

```powershell
codex mcp list
```

Затем перезапустите Codex, если серверы ещё не появились в списке инструментов. Проверьте поиск по знакомому термину в справке и запустите `bsl_diagnostics` для короткого завершённого фрагмента BSL. Не считайте сервер исправным только по наличию записи в `codex mcp list`.

Настройку серверов и необходимые домашние папки/корпус справки нужно обеспечить отдельно на каждом компьютере. Если не знаете источник сборок MCP, не скачивайте похожие программы наугад — попросите точные установочные файлы или исходный репозиторий. Не публикуйте в GitHub `v8help.toml`, базы/корпусы справки, локальные пути, токены и пользовательскую историю задач.
